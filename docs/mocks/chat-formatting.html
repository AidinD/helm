Helm-chatten: nu vs föreslaget

Samma svar från modellen, samma markdown, två renderingar. Allt till höger är visning på klientsidan - modellen skickar redan den här strukturen, så det kostar noll extra tokens. Mock för kort c6094e4f; ingenting i appen är ändrat än.

Nu - renderMarkdownInto

Fetstil, inline-kod, punktlistor och tabeller fungerar. Rubriker, kursiv, numrerade listor, citat, länkar och avdelare faller igenom som platt text. Kodblocket är ofärgat och språktaggen kastas. Texten går kant till kant.

## Vad jag ändrade

Kontextfilernas knappar frågade efter fel sorts post, så en ämnesöverlämning bad om ett projektdokument och fick Invalid project doc tillbaka. Kontrollen hade rätt; anroparen ljög.

### Tre saker

1. Knappen frågar efter den sort den *är*.

2. Ämnesöverlämningarna fick en egen rad med rubrik.

3. `HANDOFF.md (none)` är borta vid meta-home-roten.

> Vid den roten *är* ämnesfilerna överlämningarna, så appen motsade sig själv två rader isär.

Så här ser resolvern ut nu:

const docs = projectDocs.filter((d) => d.kind !== "handoffTopic");
const ref = { cwd, kind: d.kind || "projectDoc", name: d.name };
// utan d.kind hamnade allt i allow-listan för de tre namnen
chip.addEventListener("click", () => openDocViewer({ label: d.name, read }));

Varning: testet klickar varje chip och läser vad visaren visar - inte att chippet finns.

● Kodfärgerna följer temat: en färgläggare som kör lokalt, ingen nättrafik, ingen innerHTML av modelltext.

Vad som ger mest, i ordning

  1. Radlängd + luftig typografi. ~68 tecken i stället för fönsterbredd, 1.68 radavstånd, brödsnitt skilt från monospace. Det är skillnaden du pekade på i Claude Desktops Code-vy.
  2. Riktiga rubriker och listor som ankare. Två rubriknivåer med tydlig storleksskillnad, numrerade listor med egen markör, citat och avdelare - så ögat hittar tillbaka.
  3. Syntaxfärgad kod med språketikett och kopiera-knapp, färger ur temat.
  4. Callout-rutor för varning/tips, så ett "se upp" inte ser ut som vilket stycke som helst.
